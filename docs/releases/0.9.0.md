# Iris 0.9.0

## Changes since 0.8.0

### AI
- Lend another computer's GPU to a server without one: the AI worker
  (`desktop/iris_ai_worker.py`) signs in as a device, processes items that have
  no AI yet, and sends the results back.
- Choose where AI runs from the settings page, and let each account opt out.
- Libraries can move to SigLIP 2, a multilingual model, without downtime: with
  `IRIS_MODEL_NEXT` set, the worker computes the new vectors alongside the
  current ones and each library switches once every item has them.
- Text in pictures is read by Florence-2 as well, and both readings are kept.
- Documents are sorted by kind; face grouping drops avatar-sized faces and hides
  strangers seen in a single photo; taxonomy thresholds were recalibrated.

### Library
- Mark photos as favourites, and see "On this day" from earlier years on the web
  home page and at the top of the Android gallery.
- Synced media appears in an open web gallery without a reload.
- The web gallery is denser, with album covers, selection and keyboard shortcuts.
- A desktop client keeps chosen folders of a computer backed up to Iris.

### Android
- Three tabs (Photos, Albums, Search) with the backup state in the gallery bar,
  stated in words.
- Select several photos to share, trash or send to a group; restore from the
  trash; find documents and favourites under Albums.
- Choose backup folders by place instead of by path.
- The whole interface follows the device language (Portuguese or English).
- New app icon.
- Many reliability fixes for uploads, paging, token refresh and offline states.

### Web
- New logo and favicon.
- Settings page reorganised, with the AI controls; desktop devices are named in
  the device list.

## Deployment

Run `./scripts/server.sh update` from the production installation. It creates a
backup first and selects the matching release image; keep that backup for
recovery.

Moving a library to SigLIP 2 is opt-in: set `IRIS_MODEL_NEXT` and run the AI
worker until every item has the new vectors. Without it, search keeps using the
current model.

Install the 0.9.0 APK over the previous one; it is signed with the same key, so
sign-in and settings are kept.

## Release validation

This release was tagged without the staging checklist in `docs/process.md`.
After deploying, run the post-update check from that document: confirm the
version, `./scripts/server.sh status`, one completed backup, and that the app
opens and syncs.
