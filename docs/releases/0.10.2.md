# Iris 0.10.2

## Changes since 0.10.1

### Search finds what the image shows
- An item whose description was made from no text (an empty caption,
  "Tags: N/A. Visual: N/A" or taxonomy labels only) no longer counts as
  described: it is judged on its image. Those near-empty descriptions sat
  close to every short query and pushed real image matches out of the
  results.
- Description and image scores are put on the same scale before they are
  blended. Text-to-text scores sit far higher than text-to-image ones, so
  every described item used to outrank every undescribed one.
- The query translator loads right after the server starts, not on the first
  search.

### Captions for every image
- The AI worker now captions images with Florence-2 (on by default; the
  `ai_captions` setting or `--no-captions` turns it off). It is also offered
  items that already have AI but never got a caption: everything synced from
  a phone since September, and what the worker processed before.
- `scripts/backfill_descriptions.py` no longer turns a tags-only description
  into a fake caption, and writes in short transactions so uploads do not wait
  on it.

## Deployment

1. Update the server: `./scripts/server.sh update`, or **Update now** under
   **Settings › Updates**.
2. Update the AI worker on the processing computer (`git pull` in its
   checkout, then `systemctl --user restart iris-ai-worker`). Until it is
   updated it keeps working as before, without captions.
3. Libraries indexed before the `<VQA>` fix keep the echoed prompt in their
   descriptions until `scripts/backfill_descriptions.py` runs against them
   (it only re-encodes text). Take a copy of the catalogue first.

The Android app has not changed since 0.10.0.

## Release validation

On a copy of a 25k-item library, a search for "pombo" brought the two
screenshots that match it by image from outside the top 3,000 to 9th and
27th. The description repair ran against that copy first and then against the
real library: 0 echoed prompts, placeholders or fake captions remain. Staging
runs `main`, healthy. The full staging checklist and a day of use were not
done before tagging.
