# Iris 0.8.0

## Changes since 0.7.0

- Browse the web gallery as a timeline and use the updated photo viewer actions.
- Download the server's local certificate authority from System to configure
  browser trust. The page warns when its hostname is absent from the certificate.
- Keep the media library outside the installation checkout.
- Refresh staging data from a verified backup while preserving staging identity.
- Generate a missing thumbnail once when several requests need it concurrently,
  with optional background thumbnail warmup.
- Refresh account backends in the background and reuse the loaded embedding model.
- Preserve files arriving during a backup and capture catalog databases together.
- Fix similar-search crashes, capture dates for indexed files, and person faces.
- Fix Android 8/9 compatibility, gallery navigation after login, and local copies;
  improve device identification.
- Update dependencies with published security fixes.

## Deployment

After this release has been validated and published, run
`./scripts/server.sh update` from the production installation. The command creates
a backup and selects the matching release image. Keep that backup for recovery;
changing only the container image is not a substitute for restoring data if a
migration needs to be reversed.

The certificate download section appears only when Iris uses its own local CA
(`IRIS_TLS=self`). Importing the CA into a browser is a separate, manual step on
each computer. A custom certificate or an external TLS proxy requires its own
trust configuration.

## Release validation

Track completion in the release PR, using the checklist in `docs/process.md`.
Before publishing the tag, verify upgrade from 0.7.0, backup and restore, login,
gallery and search, Android lab synchronization, and certificate pairing/trust.
The presence of these notes does not mean those checks have passed.
